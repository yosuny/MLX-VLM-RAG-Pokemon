# Error Log & Fix History

## 1. Dataset Format Error
- **Error**: `ValueError: Dataset must have a 'messages' column`
- **Cause**: `train_vlm.py` (and underlying `mlx-vlm`) expects the dataset to fully conform to the chat serialization format (`{"messages": [...]}`), but our initial script generated `{"image": ..., "text": ...}`.
- **Fix**: Updated `setup_pokemon_data.py` to generate standard Chat format with user/assistant roles.

## 2. Fast Image Processor Mismatch
- **Error**: `ValueError: Only returning PyTorch tensors is currently supported.`
- **Cause**: `transformers`'s `Qwen2VLImageProcessorFast` implementation relies on PyTorch ops that clashed with the MLX environment or returned tensors incompatible with MLX conversion logic in `mlx_vlm`.
- **Fix**: Created `patched_lora.py` to explicitly force `use_fast=False` when loading the `AutoImageProcessor`. This forces the use of the Python-based slow processor which returns standard numpy/list structures that MLX handles better.

## 3. Negative Padding in Model (Feature Mismatch)
- **Error**: `ValueError: Invalid high padding size (-2079) passed to pad for axis 1.` inside `qwen2_vl.py`.
- **Cause**: The number of visual tokens generated by the image processor exceeded the number of placeholder tokens expected by the text model's embedding layer input (or vice versa), resulting in a negative pad size calculation `pad_size = inputs_embeds.shape[1] - image_features.shape[1]`.
- **Fix**: Applied a monkey patch in `patched_lora.py` to `Model._merge_input_ids_with_image_features`. The patch checks if `pad_size < 0` and truncates the image features to fit the input embedding size, preventing the crash.
